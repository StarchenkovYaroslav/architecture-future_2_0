# Проблемы

1. Медленное формирование отчетов (большой объем несегментированной информации).
2. Отсутствие авторизации (интерфейс ходит в базу).
3. Сложность управления логикой (отсутствие слоя логики, логика на уровне базы).
4. DWH не подходит для ИИ (ИИ нужны неструктерирванные данные).
5. Медленный поиск (отсутствие централизованного управления метаданными).
6. Старый sql  server.

# Приоритезация

Must have

- Медленное формирование отчетов
- Медленный time-to-market
- DWH не подходит для ИИ
- Медленный поиск

Should have

- Отсутствие авторизации
- Сложность управления логикой

Could have

- Старый sql server

## Описание архитектуры

Переход на lakehouse в формате iceberg. На первом этапе lakehouse вырастает сбоку от dwh, принимая данные из dwh в качестве одного из источников. Это позволит начать строить новую систему с единой точкой входа, минимизируя необходимость перестройки старой системы.

Те данные, которые уже идут в dwh, попадают в lakehouse через dwh. Новые данные (компания диверсифицируется) - срузу в lakehouse.

После построения lakehouse процесс попадания данных в него можно подоменно переносить из dwh, после чего полностью избавиться от sql server'a.
